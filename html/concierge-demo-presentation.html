02 · Relay Chain

How a guest issue becomes an executive-ready brief

War Room → Strategist → Executive Portal
Real handoff, not a mockup — one shared, SHA-256-signed key: TSM_HOTELOPS_STRATEGIST_RELAY
Live Demo Path
STEP 1
War Room analyzes & signs
Runs the relay bus write for domain HOTELOPS, then seals the result with a SHA-256 integrity check before writing it — a different pattern from other verticals, which write an intermediate war-relay key first.
Concierge War Room →
STEP 2
Strategist reads the signed relay
Reads directly from TSM_HOTELOPS_STRATEGIST_RELAY — the same key the War Room wrote, avoiding the class of bug seen elsewhere where a second, unreachable file held the "correct" key.
Concierge Strategist →
STEP 3
Executive Portal surfaces it
Rolls up the same signed relay key for leadership, with the integrity seal available so tampering in transit is detectable at any stage.
Concierge Executive Portal →

03 · Exception Management

What's live today — and what's still roadmap

TSMExceptions Engine · Not Yet Wired for Concierge

The Concierge Executive Portal does not currently mount a TSMExceptionWidget instance. The Incident Center persona tab has its own live-overlay incident behavior, but that is a separate, HotelOps-specific mechanism — not the shared cross-vertical TSMExceptions engine used by Healthcare and Construction.

P1
High severity, ≥90% confidence
P2
High severity, or medium severity at ≥85% confidence
P3
Everything else — open findings below the P1/P2 threshold

Honest status: mounting the shared queue on the Concierge Executive Portal is a scoped, known next step, not yet done. The Incident Center's own overlay is real and live, but it isn't the same infrastructure as the cross-vertical exception queue shown here for comparison.
