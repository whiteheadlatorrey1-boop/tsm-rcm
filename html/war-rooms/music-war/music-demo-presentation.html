Sweet Music™ OS · Creative Tools Vertical

Not a relay chain.
A creative toolkit with a live 3-agent core.

Sweet Music OS doesn't follow the War Room → Strategist → Executive Portal pattern the rest of the platform uses — it's a standalone suite of creative tools (cadence coaching, beat/song building, mixing/mastering guidance, release planning) that share state through a lightweight localStorage bus, plus one genuinely live multi-agent feature: a real sequential ZAY → RIYA → DJ AI chain, runnable from the presentation deck itself.

02 · Highlight Reel

The two moments to lead with: Cadence Studio, Live Agent Chain

Both of these are Playwright-verified this session (tests/e2e/demo/music-demo.spec.js), not staged screenshots. Cadence Studio is the safer opener — low-stakes, fast turnaround. The live agent chain on the presentation deck is the bigger swing: three real sequential Groq calls, each refining the last.

ACT 1Cadence Studio — live per-bar flow coaching
war-rooms/music-war/cadence-builder.html
1.1 TYPE · 4 bars into the lyric rows .lyric-input → live syllable count per bar
Every bar gets scored against the target syllable count the instant you finish typing it — no submit button, no round trip.
1.2 CLICK · ANALYZE FLOW .btn.btn-amber → analyzeFlow()
Now I hand these bars to the cadence AI coach — watch the feedback panel.
SHOWA real SMOS.askJSON() call streams back a per-bar score, an overall note, and specific rewrite suggestions — genuinely generated for these exact bars, not a canned response.
HONESTThis call was truncating mid-JSON on real 4-bar inputs until this session's fix (maxTokens 1000→1600 plus a truncation-repair fallback in sweet-music-engine.js) — worth a fresh double-check before a live demo if it's been a while since the last run.
ACT 2Presentation Deck — the live ZAY → RIYA → DJ chain
war-rooms/music-war/presentation-live.html
2.1 ADVANCE · to the agent-chain slide [data-tsm-action="next"] ×4 from slide 1
This deck is the pitch itself, built on the same platform — and it's showing real, live slide state as we go, not a static export.
2.2 CLICK · RUN ZAY → RIYA → DJ button[data-tsm-action="runLiveChain"] → POST /api/music/agent/chain
This is the moment to slow down for. Three real, sequential AI calls: ZAY refines cadence and flow, RIYA takes that and works the emotion and imagery, DJ takes RIYA's draft and locks the hook and structure. Each one builds on the last.
SHOWThe result box fills in with the final, DJ-refined draft once all three hops complete — give it a few seconds, this is three sequential Groq calls, not one.
HONESTThis exact button was broken until this session — a duplicate click-dispatcher script on this page was firing every click twice, which desynced the slide index and hid this button behind the wrong slide. Confirmed fixed and Playwright-verified, but it's a good one to smoke-test right before you're live.

04 · Honest Status

What's live today — and what still needs work

Verified This Session · Source-Checked, Not Assumed
Fixed SMOS.askJSON() was truncating mid-JSON on real multi-bar Cadence Studio requests (default 1000-token cap). Bumped to 1600 with a truncation-repair fallback. Affects all 5 askJSON() call sites: Cadence Studio, Beat Workbench, Producer AI, Mixing Coach, Mastering Coach.
Fixed Presentation deck had a duplicate [data-tsm-action] click dispatcher — every button (slide nav, live chain) fired twice per click. Removed; /shared/tsm-shared.js's dispatcher was already sufficient.
Broken SMOS.nav.base in sweet-music-engine.js string-matches a /music-command/ path segment that no real deployed URL contains (real pages live under /war-rooms/music-war/). Every SMOS.nav.toX() call — including both live producer-widget nudges (Song Builder→Cadence Studio, Dashboard→Song Builder) and Cadence Studio's own "Load from Song Builder" button — currently 404s. Not yet fixed; flagged this session, not scoped into this pass.
Not Wired "Generate 10 Hooks · $25" appears only as static copy on the Marketing and How-To-Guide pages — no button, form, or handler anywhere in the app actually calls it. Don't demo it as a live feature.
