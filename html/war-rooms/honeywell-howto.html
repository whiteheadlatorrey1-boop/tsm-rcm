What's in Honeywell, and how to use it

Unlike a single-property vertical, Honeywell is split across three independent incident command centers — Plant, Supplier, and Cyber/OT — each running its own 6-engine AI analysis. All three relay into one shared Strategist, which rolls up into one Executive Portal. This guide covers each war room, the shared engine pattern, and how the relay chain connects them.

The 6-Engine Pattern shared across all three

All three war rooms follow the same shape: Engine 01 extracts and structures the incident facts, Engines 02–03 quantify impact and cause, Engine 04 calculates financial exposure (and emits a machine-readable KPI_JSON line the page parses for the KPI bar), Engine 05 produces a ranked, owner-and-deadline action plan, and Engine 06 packages an executive decision brief — the same payload the Strategist and Executive Portal consume.

Strategist honeywell-strategist.html

One shared strategist view for all three domains. It reads whichever of the three relay keys was written most recently (TSM_HONEYWELL_PLANT_RELAY, TSM_HONEYWELL_SUPPLIER_RELAY, TSM_HONEYWELL_CYBER_RELAY), shows the source badge and full 6-engine output, and lets you acknowledge or escalate to the Executive Portal.

A legacy unscoped key (TSM_HONEYWELL_RELAY) is still read as a last-resort fallback for any pre-split session data, but nothing writes to it anymore.

Executive Portal honeywell-executive-portal.html

Rolls up whatever the Strategist escalated — financial exposure, the domain-specific secondary/tertiary KPI, and executive actions (authorize / escalate / review) ready for sign-off.

Data & Relay Flow how it connects

  • War room → Strategist: each war room writes its own domain-scoped relay key on both localStorage and sessionStorage, and also calls window.TSM.relay.write() with a domain tag (e.g. HONEYWELL_PLANT) so it shows up in the shared relay bus.
  • Strategist → Executive: escalating from the Strategist writes TSM_HONEYWELL_EXEC_RELAY and creates a Mission Core record (vertical: honeywell) via TSMMissionModel.createMission(), so it also shows up in cross-vertical mission rollups.
  • Live updates: the Strategist listens for storage events on all three relay keys, so if you have the Strategist open in one tab and run a new analysis in a war room in another, it updates automatically without a manual refresh.
