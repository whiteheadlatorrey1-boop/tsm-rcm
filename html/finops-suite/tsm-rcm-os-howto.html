What RCM OS Is — and Isn't

RCM OS is the map of the close, not the engine that runs it. It sequences your daily entries, weekly sweeps, and month-end close into one cadence, and tells you exactly which module owns each step — but the actual postings, reconciliations, and reports still happen inside the individual app files (finops-operations.html, finops-accounting.html, compliance.html, and the rest).

Think of RCM OS as the checklist and dashboard that sits above your existing tools. It answers three questions at any moment: what do I do today, why does it matter, and which file do I open to actually do it?

Interface Guide

Getting Oriented

Every screen in RCM OS is built from the same handful of elements. Learn these once and every tab — Daily, Weekly, Month-End, Framework — reads the same way.

Module Rail
The left-hand column. Every connected app file, color-coded by category (Operations, Accounting, Compliance, Enterprise, Forecasting, Vendor, Logistics, Search). This is your directory — if you don't know which file to open, look here first.
Cadence Toggle
Top bar buttons: Daily / Weekly / Month-End / Controller Framework / Executive. Switching tabs changes everything below it — the phases, the closing protocol, and the completion gauge all belong to whichever cadence is selected. Executive swaps the phase cards out for the Executive Summary — see Data Intake below.
Relay-Received Modal
Pops automatically the first time you land on RCM OS after sending a document over from FinOps Doc Showcase. Confirms the hand-off, names the document, and shows exactly which of the four engine outputs arrived and where each one routed. See Data Intake: Showcase → RCM OS.
AI Assistant (🤖 fab, bottom-right)
A standing copilot, not a search box. Opens with the same ranked, severity-scored briefing as the Proactive Guidance card, and answers questions about how to use RCM OS or any connected module. See The AI Assistant.
Reconciliation Flow Board
The horizontal chain (Daily Entry → Weekly Sweep → Month-End Close → Annual Cycle). It's clickable — click any node to jump straight to that cadence. It exists to remind you these aren't four separate systems; they're one data trail tightening in scope.
Completion Gauge
Shows what percentage of the current cadence's tasks are checked off this session. Green (80%+) means you're on track to close clean; amber or red means items are still open.
Open Exceptions Gauge
A placeholder count of unchecked tasks in the current cadence. Once compliance.html has a live flag feed, this should be wired to real exception data instead — see the note in the Module Directory below.
Phase Cards
Each cadence breaks into 3–5 phases (e.g. "Morning Kickoff & Branch Controls"). Every phase names its owning module, the purpose of the work, and a checklist of concrete tasks. Check tasks off as you complete them in the real module.
Closing Protocol
The lock-step sequence that ends each cadence (e.g. Cash-to-Ledger Matching → Exception Flagging → Daily Log Closure). This is the sign-off order — don't skip ahead to step 3 before step 1 is done.
Close Checklist (Month-End only)
The 12-item final sign-off list, organized around the ABCDE mnemonic. Nothing on this list should be a surprise if the daily and weekly cadences were followed all month.
How Data Gets In

Data Intake: FinOps Doc Showcase → RCM OS

RCM OS doesn't sit in isolation — it's the landing pad for whatever FinOps Doc Showcase (finops-showcase-v1.html) just analyzed. This is the intended entry point for a real document, not just the module rail.

1
Run the engines in Doc Showcase
Upload or select a document in finops-showcase-v1.html and fire its analysis engines (triage, variance/risk, controller action plan, CFO brief). The ⇄ SEND TO RCM OS button stays disabled until there's an actual analysis to relay — it won't let you send an empty run.
finops-showcase-v1.html
2
Click ⇄ SEND TO RCM OS
The four engine outputs are staged server-side (with a localStorage fallback if the relay endpoint is unreachable) and the browser navigates you straight to tsm-rcm-os.html.
3
The ✓ RELAY RECEIVED modal confirms the hand-off
On arrival, RCM OS checks for an unseen relay and — if found — opens a modal naming the document and timestamp, then lists exactly where each piece of the analysis routed:
Engine outputRouted to
Document Triage & Flag AnalysisCompliance Desk (compliance.html)
Variance & Risk IntelligenceAccounting Ledger (finops-accounting.html)
Controller Action PlanToday's Cadence Tasks (Daily / Weekly view)
CFO Executive IntelligenceExecutive Tab (this workspace)
Any route the current document didn't actually produce shows dimmed rather than disappearing — so you can see the full menu of what could arrive, not just what did. Dismiss closes it; View in Document Intake jumps you to the populated intake card.
4
Remediate from the Proactive Guidance card or the Assistant
Every routed item also feeds the ranked, severity-scored guidance queue (see The AI Assistant) — each entry names the concrete next action, which module owns it, why that's the right route, and what's at risk if it sits. That's the actual anomaly-remediation path: relay in, guidance ranks it, you act in the named module.
5
Switch to the Executive tab to see it rolled up
The Controller Action Plan and CFO Executive Intelligence blocks populate automatically once a document has been relayed. From there, ↓ Export Executive Report compiles the cadence completion stats, open-exception count, Controller Action Plan, and CFO brief into one downloadable report — the closest thing RCM OS has today to a real one-click export.
Executive Tab
Nothing relayed yet? The Executive tab and Document Intake card stay in an honest empty state ("No document has been relayed from FinOps Doc Showcase yet") rather than showing fabricated placeholder data.
Copilot, Not Search Box

The AI Assistant

The 🤖 fab in the bottom-right corner is a standing copilot — it leads with guidance instead of waiting to be asked something.

Opens with a briefing, not a greeting
First open pulls the same ranked, severity-scored, next-best-action list shown on the Overview tab's Proactive Guidance card — so the assistant and the dashboard never disagree with each other; it's one guidance engine surfaced in two places.
Guides you through curing anomalies
Each guidance item names the concrete next action, the module that owns it, why that's the right route, and what's at stake if it sits — a systematic path from "here's an anomaly" to "here's the exact tool and step to fix it," not just a flag.
Answers app questions too
Ask it things like "how do I use the Compliance Desk?" and it answers grounded in a built-in knowledge base of RCM OS's modules and cadences, rather than guessing.
Degrades honestly, never fabricates
If the Groq-backed guidance engine is unreachable, the assistant and the Proactive Guidance card fall back to a real keyword scan of the relayed data instead of inventing an answer — the feature narrows, it doesn't lie.
Honest limitation: guidance quality depends on a live GROQ_API_KEY being configured. Without it, expect the fallback keyword-scan behavior described above rather than the full ranked analysis.
Cadence Walkthrough
DAILY · 6:00 AM – 6:00 PM

Running Your Day in RCM OS

Open the Daily tab first thing each morning. Work top to bottom — each phase feeds the next.

1
Open finops-operations.html and clear Morning Kickoff
Pull the overnight cash receipt batch, verify queued AP invoices, and confirm yesterday's AR postings. Check off each task in RCM OS as you confirm it in the module — don't check a box you haven't actually verified.
finops-operations.html
2
Switch to finops-accounting.html for Ledger & Expenditure Tracking
Post the day's journal entries and compare department burn rate to budget. Flag anything over a 5% variance right away — this is what prevents a surprise at the weekly sweep.
finops-accounting.html
3
Mid-day, run the compliance.html exception review
Scan the compliance dashboard for flags, confirm missing-documentation requests went out, and escalate anything high-severity. This keeps audit-readiness a daily habit instead of a month-end scramble.
compliance.html
4
Close the day with the Daily Reconciliation Protocol
Cash-to-Ledger Matching → Exception Flagging → Daily Log Closure. Once the ledger is locked, that day's entries are part of the immutable audit trail — treat lock as final.
finops-operations.html → compliance.html → finops-accounting.html
Tip: If you're behind, don't skip a phase — finish it late rather than leave it unchecked. RCM OS's weekly sweep assumes every day's numbers are real.
Cadence Walkthrough
WEEKLY · Every Friday, 1:00 – 4:00 PM

Running Your Week in RCM OS

Weekly is where you zoom out from single transactions to trends. Budget drift, compliance posture, and everything owed to vendors and carriers gets reviewed here — before it becomes a month-end surprise.

1
Roll up the week in finops-accounting.html
Aggregate the week's journal entries by department, re-run the budget-to-actual threshold check, and review any unapplied cash or negative balances.
finops-accounting.html
2
Spot-check controls in compliance.html
Confirm segregation-of-duties is holding, all of the week's flags were resolved, and documentation is complete for large transactions.
compliance.html
3
Review liability in the Vendor Situation Room
Check outstanding vendor invoices and due dates, verify recurring subscription and contract costs, and flag any duplicate or disputed charges.
supplier-vendor-situation-room.html
4
Sync operational exceptions in the Logistics Situation Room
Match freight or carrier disputes to pending AP holds, and confirm inventory receipts match vendor invoices — this is where operational problems become financial exposure.
logistics-situation-room.html
5
Close the week with sign-off
Variance Sign-off → Compliance Attestation → Vendor Liability Snapshot. This snapshot becomes next week's baseline.
finops-accounting.html → compliance.html → supplier-vendor-situation-room.html
Cadence Walkthrough
MONTH-END · Last 3 business days

Running Month-End in RCM OS

This is the shift from daily maintenance to aggregate reporting. If the daily and weekly cadences were followed, month-end is packaging and sign-off — not discovery.

1
Enterprise Performance & Variance Analysis
Pull cross-vertical posture scores, aggregate department budgets and actuals, and compare against the month's forecast.
tsm-finops-enterprise-management.html
2
Scenario Modeling & Adjustment
Run predictive scenarios off this month's variance data, and document any operational levers to pull if a branch is trending over budget.
finops-scenarios.html
3
Vendor & Accounts Ledger Audit
Reconcile all outstanding vendor invoices and confirm every vendor payment is fully accounted for before the books close.
supplier-vendor-situation-room.html
4
Final Compliance & Audit Packaging
Generate the GAAP adherence report and assemble supporting documentation so everything satisfies internal controls and external regulators.
compliance.html
5
Executive Reporting
Compile the income statement, balance sheet, and cash flow statement, draft the MD&A summary, and deliver the packaged report to branch leadership and the CFO.
finops-accounting.html + Enterprise Suite

Where the Numbers Actually Come From

Generating Reports from RCM OS + Its Modules

RCM OS doesn't generate reports itself — it tells you which module to open and in what order. Here's the recipe for the reports people ask for most, and exactly which module produces each one.

Executive Report (one-click export)
Any time, once a document has been relayed
The one real export button in RCM OS today. Switch to the Executive tab and click ↓ Export Executive Report — it compiles cadence completion percentage, the open-exceptions count, the Controller Action Plan, and the CFO Executive Intelligence brief into a single downloadable file. Requires a document to have been relayed from FinOps Doc Showcase first; otherwise the Executive tab stays in its empty state.
Executive Tabfinops-showcase-v1.html
Daily Cash & Exception Snapshot
Daily, end of day
After the Daily Reconciliation Protocol locks the ledger, export the day's cash-to-ledger match results and any open compliance flags. This is the fastest read on "did today close clean."
finops-operations.htmlcompliance.html
Weekly Vendor Liability & Variance Summary
Weekly, Friday close
Pull the budget-to-actual variance summary from the accounting ledger, then the outstanding invoice list from the Vendor Situation Room. Combine into one memo for branch leads: what drifted, and what's owed.
finops-accounting.htmlsupplier-vendor-situation-room.html
Month-End Executive Pack (Balance Sheet + P&L + MD&A)
Monthly, close week
This is the big one, and it's a compile job, not a single export:
1) Trial balance and GL detail from the accounting ledger.
2) Cross-vertical posture and variance from the Enterprise Suite.
3) Vendor liability position from the Vendor Situation Room.
4) Compliance and audit-trail sign-off from the Compliance Desk.
Stack these in that order, write the MD&A summary over them, and that's your executive pack.
finops-accounting.htmltsm-finops-enterprise-management.htmlsupplier-vendor-situation-room.htmlcompliance.html
Compliance & Audit Trail Export
Weekly spot-check · full export at month-end
Generate the GAAP adherence report and export the append-only audit log. This is what you hand an external auditor — it should never need reconstruction after the fact, because it was built daily.
compliance.html
Forward-Looking Scenario Brief
Monthly, before the new period opens
Run a scenario off the current month's real variance data, and document the levers you'd pull if a branch is trending over budget. Attach this to the executive pack as the "what we're watching next month" section.
finops-scenarios.html
Honest limitation: outside of the Executive Report export above, the module files referenced here are demo/blueprint tools today — most don't yet have a one-click "export PDF" button. Until they do, "generating a report" means opening the relevant module, reading off the current figures, and compiling them into your document or slide of choice. Treat those recipes as the assembly order, not a literal export button to click.
